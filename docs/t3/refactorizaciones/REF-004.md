# REF-004: catálogo de horarios a MVP/repositorio

## 1. Problema inicial

FrmMantHorarios validaba y guardaba con HorarioMapper, asignaba MAX+1 y creaba infraestructura desde el evento. Esa ruta corresponde al catálogo: no es el registro de periodos temporales RF-01.

Vista pasiva que reenvía eventos, presenter que coordina casos y repositorio específico PostgreSQL creado en CompositionRoot. Se conservan nombres de formularios y controles. Mantenimiento preventivo por separación de responsabilidades; correcciones de comportamiento se declaran aparte en la spec TEC correspondiente.

```csharp
    private void Guardar()
    {
        if (!_cargado) return;
        _view.HabilitarGuardar(false);
        try
        {
            var resultado = _guardar.Ejecutar(new HorarioDto
            {
                Id = _view.IdHorario, Descripcion = _view.Descripcion, Estado = _view.Estado,
                Ingreso1 = _view.Ingreso1, Salida1 = _view.Salida1,
                Ingreso2 = _view.Ingreso2, Salida2 = _view.Salida2
            });
            if (resultado.Exitoso)
            {
                _cargado = false;
                _view.CerrarGuardado();
            }
            else _view.MostrarError(resultado.Mensaje);
        }
        catch (Exception ex) { _view.MostrarError("No se pudo guardar el horario: " + ex.Message); }
        finally { if (_cargado) _view.HabilitarGuardar(true); }
    }
```

## 5. Principio aplicado

SRP: formulario captura/reenvía y HorarioEditorPresenter coordina GuardarHorario. DIP: caso depende de IHorarioRepository; CompositionRoot elige PostgreSqlHorarioRepository. DRY: Horario concentra validación de las cuatro horas.
