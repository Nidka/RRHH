## Problema y comportamiento actual

En la base no hay tabla, repositorio ni pantalla de teletrabajo. El diagnóstico corresponde a la inspección estática de la reconstrucción y de BD/schema.sql. Queda pendiente contrastar el ejecutable original.

## Resultado esperado y alcance

Registrar y listar periodos por código de empleado con fechas inclusivas y modalidad total o parcial. **Hipótesis:** parcial se representa con días remotos fijos por semana (lunes a viernes), de uno a cuatro. La autorización se guarda como referencia opcional de hasta 200 caracteres. La anulación queda fuera hasta acordar quién puede anular y qué ocurre con el historial. El acceso usa el menú de mantenimiento de asistencia existente, sujeto a confirmar permisos específicos de teletrabajo.

### Propuesta para Kadin

| Columna | Contrato propuesto |
|---|---|
| Id | integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY |
| IdEmpleado | integer NOT NULL |
| FechaInicio, FechaFin | date NOT NULL, CHECK FechaInicio <= FechaFin |
| Modalidad | char(1) NOT NULL, T o P |
| DiasRemotos | integer NOT NULL, máscara lunes=1 a viernes=16. T usa 31, P usa 1–30 |
| Autorizacion | varchar(200) NULL |
| Estado | boolean NOT NULL DEFAULT true |
| FechaRegistro | timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP |

Tabla `public."Teletrabajo"`. Índice por IdEmpleado, FechaInicio, FechaFin. Sin FK hasta revisar datos de Empleado. Evaluar una restricción de exclusión si habrá escritores ajenos. Kadin conserva la migración y su reversión. No hay DDL del módulo en esta rama. El patrón remoto es el complemento del patrón presencial dentro de lunes a viernes.

## Criterios de aceptación

- Un empleado único y existente obtiene un ID al registrar un periodo válido. Un intervalo de un día es válido.
- Igualdad, cruce o contención con un periodo activo del mismo empleado se rechazan. Otro empleado no bloquea.
- Rango invertido, modalidad inválida, patrón inválido o empleado inexistente se rechazan.
- El listado por código muestra periodos registrados y el error de infraestructura se informa en la vista.

## Impacto y diseño

Mantenimiento adaptativo por nueva modalidad. Capacidad nueva, sin refactor del flujo existente ni reemplazo de procedimiento. MVP: FrmTeletrabajo → ITeletrabajoView/TeletrabajoPresenter → casos de uso → ITeletrabajoRepository → PostgreSqlTeletrabajoRepository. CompositionRoot conecta las dependencias. SRP separa captura, regla y persistencia. DIP permite probar los casos de uso con un repositorio falso. RangoFechas concentra la semántica inclusiva existente.

| Capa | Cambio y riesgo |

| Domain | PeriodoTeletrabajo valida entrada y usa RangoFechas para límites. |
| Application | RegistrarPeriodoTeletrabajo, ListarPeriodosTeletrabajo y contrato de persistencia atómica. |
| PostgreSql | SQL con fechas tipadas. Bloqueo de tabla para serializar comprobación e inserción. Bloqueo compartido de Empleado para verificar existencia durante la escritura. |
| Presentation y vista | Eventos y grilla tipada. Acceso desde el menú de asistencia mediante composición. |
